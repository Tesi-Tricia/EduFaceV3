Running EduFace (static HTML edition)

This edition has no server and no database. The pages run in the browser and keep all data inside that browser (IndexedDB) on that one computer.

Start it

  1. Double-click start.bat. A black window opens: it is a tiny web server that works only on this computer. Leave it open.
  2. Your browser opens http://localhost:8080. (Use Chrome or Edge. The address must say localhost: browsers only allow the camera on localhost or https.)
  3. First time: create the school and the administrator. No internet is needed.
  4. Install it as an app (browser menu → Install EduFace). Afterwards it opens even when start.bat is not running.

What "data stays in this browser" means

  • Another browser, another Windows user, or another computer sees nothing. A gate tablet and an office PC do not share records.
  • Clearing browsing data, a private/incognito window, or a disk clean-up can delete everything.
  • Therefore: make an encrypted backup (Backup page) at least weekly and keep the file and its passphrase safe, in different places.
  • If the administrator password is forgotten, the data cannot be recovered (it is encrypted on purpose).

Best way to use it at a school

  • One computer with a webcam at the gate (or the office) runs the app in Gate kiosk mode. That same computer holds all the data.
  • Enable BitLocker, set a Windows password, lock the room. The app's passwords protect against honest mistakes; they cannot stop someone who controls the computer.
  • Need several gates or tablets sharing live data? This edition cannot do that. Use the server edition (separate project) instead.

Moving to another computer

  1. Backup page → Download backup (choose a passphrase).
  2. On the new computer open the same folder, create any temporary school, then Backup → Restore with the file and passphrase. Everyone signs in again with their old passwords.

Messages to guardians

A browser cannot send SMS by itself. EduFace queues the messages; on a phone or tablet the Send button opens the SMS app with the text ready. Or use Export CSV for a bulk-SMS service.

Camera and speed

  • After signing in, the face engine prepares itself for a few seconds (a banner says so). The very first time on an older computer the screen can pause for up to a minute while the graphics chip compiles its programs; the next times take about 5 seconds. QR cards work meanwhile. After that a scan takes roughly 0.2–0.5 s on a normal computer.
  • If the computer has only a very old graphics chip and the pause is a problem, turn off Prepare the face engine when someone signs in in Settings, and sign in once before the school day starts.
  • Good, even light on the face matters more than camera resolution.

Known limits (be honest with the school)

  • No anti-spoofing: a printed photo or a phone screen could fool the face scan. Do not use it as proof of identity.
  • Accuracy has not been measured on your students and camera. Run the accuracy test (Help → Accuracy test) before relying on it.
  • Security is client-side: someone with full control of the browser can bypass screen locks. Protect the computer itself.
  • No automatic SMS, no live sync between devices, no central server.
